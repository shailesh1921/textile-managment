ABSTRACT

The commission-based textile processing cluster (e.g., Surat, Tirupur, Ahmedabad) operates on high volume, tight turnaround windows, and multi-stage chemical recipes. However, traditional standalone accounting packages or generic ERPs fail to address the core physical and regulatory constraints of textile wet processing—namely: dual Unit of Measure (UOM) conversions (inwarding in meters vs. chemical dosing by fabric mass in KG), stage-wise shrinkage and process loss tracking, ASTM D5430 4-Point visual defect scoring, and GST Section 143 job-work tax compliance.

This project delivers a production-ready, cloud-native, multi-tenant Textile Enterprise Resource Planning (ERP) suite engineered with React 18, Vite, Node.js/Express, and Neon Cloud Serverless PostgreSQL. Key contributions include: (1) an automated roll-level (Taka) traveler system with streaming PDFKit QR code Lot Cards, (2) an intelligent batch scheduler with liquor ratio chemical dispensing calculations, (3) real-time utility consumption logging (Coal, Gas, Steam, Electricity), (4) automated ASTM D5430 4-point QC audit matrix with spectrophotometer CIELAB Delta E shade tolerance checks, and (5) dynamic per-lot cost sheet margin analysis factoring raw materials, fuel overheads, and machine hourly rates.

CHAPTER 1: INTRODUCTION & DOMAIN BACKGROUND

1.1 Background & Motivation

In commission dyeing and printing mills, fabric is received as 'Grey Fabric' (raw woven/knitted fabric) from traders or weavers. The mill processes the fabric through various chemical and mechanical stages and dispatches finished goods back to the trader under Job-Work contracts.

1.2 Key Domain Challenges Addressed

  • Dual Unit of Measure (UOM) Conversion: Automated dynamic derivation of mass in KG from meters using fabric width and GSM.
  • Cumulative Process Shrinkage: Stage-by-stage shrinkage logging to ensure exact bill reconciliation.
  • Utility Fuel Costing: Real-time allocation of coal, gas, steam, and power costs directly to batch runs.
  • ASTM D5430 4-Point Quality Inspection: Automated calculation of penalty points per 100 sq. meters with pass/fail evaluation.
  • GST Section 143 Compliance: Generation of Delivery Challans with transporter LR logging.

CHAPTER 2: SYSTEM ARCHITECTURE & DATA DESIGN

2.1 High-Level Architecture

The system adopts a modern 3-Tier cloud architecture: React 18 SPA Frontend → Node.js/Express RESTful API Backend → Neon Cloud Serverless PostgreSQL Database with multi-tenant UUID partitioning.

2.2 Database Relational Model (28 Relational Tables)

Structured across 5 operational domains: Identity (tenants, users, roles), Master Registries (parties, fabrics, shades, chemicals, machines, templates, recipes, rates), Operations (job_orders, lots, lot_takas, batch_runs, batch_utility_logs), Quality (qc_inspections, qc_defect_entries, lab_tests), and Accounting (packing_lists, dispatch_challans, party_ledger, lot_cost_sheets).
